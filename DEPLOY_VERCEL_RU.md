# Деплой MAKEROW TEAMWORK на Vercel — инструкция на русском

## 1. GitHub

1. Открой https://github.com/new.
2. Создай репозиторий `makerow-teamwork` и обязательно поставь **Private**.
3. Распакуй ZIP проекта на компьютере.
4. На GitHub нажми **Add file → Upload files** и перетащи содержимое папки проекта (не сам ZIP): `package.json`, `vercel.json`, `src/`, `api/`, `static/`, `index.html`, `vite.config.ts`, конфиги и README.
5. Нажми **Commit changes**.
6. Проверь, что в корне репозитория лежат `package.json`, `vercel.json`, папки `src`, `api`, `static`.

Не загружай `.env`, токены или реальные пароли. В `.gitignore` уже исключены `.env` и локальные секреты.

## 2. Подключить Vercel

1. Открой https://vercel.com/new.
2. Выбери **Continue with GitHub** и разреши доступ к новому приватному репозиторию.
3. Нажми **Import** напротив `makerow-teamwork`.
4. Framework Preset: **Vite** (обычно определяется автоматически).
5. Root Directory: `./`.
6. Build Command: `npm run build`.
7. Output Directory: `dist`.
8. Install Command: `npm install`.
9. Не нажимай Deploy, пока не подключена база и не добавлены переменные — см. ниже. Можно сначала импортировать проект, а затем добавить env и развернуть.

## 3. Создать Neon PostgreSQL

1. В Vercel открой свой проект → **Storage** или **Marketplace**.
2. Найди интеграцию **Neon** (Postgres) и нажми **Install / Connect**.
3. Создай новую Neon database (Free plan, если доступен для аккаунта) и выбери проект Vercel.
4. Подключи интеграцию к окружениям **Production** и **Preview** при необходимости.
5. Проверь, что в Vercel → Settings → Environment Variables появилась `DATABASE_URL`.
6. Используй pooled connection string, если Neon предлагает выбор pooled/direct для веб-приложения.

Если интеграция создала другое имя переменной, добавь вручную `DATABASE_URL` с Neon pooled connection string.

## 4. Добавить переменные окружения

Открой Vercel → Project → Settings → Environment Variables. Добавь переменные для Production:

| Имя | Значение |
|---|---|
| `ADMIN_USERNAME` | желаемый логин администратора, например `makerowadmin` |
| `ADMIN_PASSWORD` | уникальный пароль не короче 16 символов |
| `LZT_API_TOKEN` | LZT Market API token с доступом к `steam-value` |
| `APP_ENCRYPTION_KEY` | 32-байтовый ключ шифрования персональных STRATZ-ключей (создай командой `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"`) |
| `DISCORD_BOT_TOKEN` | новый Discord Bot Token после Reset Token |
| `DISCORD_CHANNEL_ID` | `1573865134806270074` |
| `COOKIE_SECURE` | `true` |
| `NODE_ENV` | `production` |

`DATABASE_URL` должна быть добавлена Neon-интеграцией. Не добавляй `STRATZ_API_TOKEN`: каждый пользователь вводит свой STRATZ API Key после входа в приложение, в разделе «Мои API-ключи». Сервер шифрует ключи отдельно для каждого аккаунта с помощью `APP_ENCRYPTION_KEY`. Не создавай переменные с префиксами `VITE_` или `NEXT_PUBLIC_`.

Для защиты не вставляй токены в GitHub, исходники или сообщения. Ранее раскрытый Discord-токен нужно сбросить в Developer Portal.

## 5. Первый Deploy

1. Вернись в Vercel → Deployments.
2. Нажми **Redeploy** или создай новый commit в GitHub.
3. Дождись успешной сборки.
4. Открой адрес вида `https://makerow-teamwork-....vercel.app`.
5. При первом обращении к API приложение создаст таблицы в Neon и первоначального админа из `ADMIN_USERNAME` / `ADMIN_PASSWORD`.
6. Войди с этими данными. Новые аккаунты регистрируются только с действительным инвайтом; инвайты генерируются админом в панели.

Если переменные окружения менялись после деплоя, сделай **Redeploy**. Не меняй `APP_ENCRYPTION_KEY` после того, как пользователи сохранили STRATZ-ключи: без прежнего значения их нельзя будет расшифровать. Сохрани его в надёжном менеджере паролей.

## 6. Проверка работоспособности

- Открой `https://ТВОЙ-ДОМЕН/api/health` — должен вернуться JSON с `ok: true`.
- Войди как админ.
- Создай одноразовый инвайт и проверь регистрацию в приватном окне.
- Проверь блокировку/разблокировку тестового аккаунта.
- Войди под своим аккаунтом, открой «Мои API-ключи» и сохрани собственный STRATZ API Key.
- Проверь LZT на одном публичном Steam-профиле.
- Проверь Discord только после добавления бота в сервер и предоставления ему доступа к каналу.

## 7. Как обновлять сайт

Измени файлы проекта на компьютере, загрузи изменения в тот же GitHub-репозиторий и нажми Commit. Vercel автоматически создаст новый deployment.

## Примечания

- Vercel Hobby предназначен для личного некоммерческого использования. Для коммерческого сервиса проверь актуальные условия и план.
- Для Hobby Vercel Functions с Fluid Compute имеют максимальную длительность 300 секунд; проверка матча запускает LZT-запросы последовательно с интервалом, поэтому обычная проверка пяти/десяти игроков занимает десятки секунд.
- Vercel Functions не поддерживают вечный фоновый цикл. Поэтому check API отвечает только после завершения проверки; индикатор в интерфейсе показывает загрузку, затем отображаются итоговые статусы.
- Новая версия использует Neon PostgreSQL вместо локальной SQLite. Локальная база из предыдущего архива автоматически не импортируется. Создаётся новая база и один первоначальный администратор.
- Бесплатные квоты и доступность интеграции зависят от актуального аккаунта и тарифов провайдеров; постоянный бесплатный хостинг без лимитов не гарантируется.
